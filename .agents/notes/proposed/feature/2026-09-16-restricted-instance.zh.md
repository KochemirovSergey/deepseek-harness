# Agent Note: 管理员控制的受限实例

Status: proposed

[English](2026-09-16-restricted-instance.md) | 中文

## 问题

共享浏览器不能让用户获得宿主进程管理凭据、插件、模型路由或任意宿主文件的权限。 普通 workspace-write 策略限制写入，但允许读取。隐藏控件不能保护直接 Remote 调用。

## 提案

此分支的实现先读取 `DSH_INSTANCE_POLICY`，再处理项目环境文件或配置文件。 仅支持 Linux 的 JSON 文件及其祖先路径必须是规范路径，由 root 拥有，且组和其他用户 不可写入。无效配置阻止启动。不可变策略固定 workspace、模型、preset，以及可选的 推理强度和输出上限。启动时的 `DSH_HOME` 必须被明确保护。受限启动忽略项目 `.env`； 普通启动保留现有行为。

Remote 分发在激活 Agent 前使用默认拒绝的操作列表。Session 所有者拒绝执行控制参数， 模型分发与沙箱所有者分别落实管理员的值。设置写入、凭据写入、OAuth UI、插件管理、 斜杠命令、Cordis 和工作流执行不可用。首个实现禁用子智能体执行和继续操作，因为外部 provider 并非都继承相同的操作系统限制。

Shell 和固定文件系统 worker 使用完整 Landlock、明确的读取授权及清理后的环境。 文件系统 worker 在子进程中调用 LocalFileSystem；词法检查本身不是安全机制。 内容寻址的附件保留在私有存储中。独立的受限发布进程将验证后的附件字节流写入 workspace 副本；后续请求可以依据原始 ID 恢复这些副本。

浏览器从启动清单接收不可变能力。它保留导航和平面会话列表，隐藏管理控件并显示固定 模型。继承的启动环境中设置 `DSH_MAINTENANCE_AUTH=1` 会选择临时浏览器签名密钥， 不会替换普通浏览器凭据。部署必须在维护期间停止用户服务并持有同一配置文件锁。

## 考虑过的替代方案

**仅使用 UI 控件。** 直接请求和智能体工具仍会拥有管理权限。

**在宿主进程中验证路径。** 验证与打开之间替换符号链接仍可访问凭据。 操作系统必须拒绝实际的子进程系统调用。

**向 shell 授予附件存储访问权。** 这会把通用文件访问扩展到 state。 宿主仅按验证过的 ID 读取，再复制到用户 workspace。

## 验收标准

实现尚未安装到用户服务。验收需要普通模式回归、真实 Linux 拒绝、无密钥的 构建产物快照及浏览器流程，再在独立发布的构建上验证 Sol、令牌刷新、OV 只读访问、 重启、维护和回滚。现有 Session 历史必须逐字节保持不变；新请求记录必须描述实际模型 和沙箱策略。

## 风险

这是共享 workspace，并非用户间隔离。网络目的地限制和资源配额不在范围内。 读取授权必须排除所有凭据和 state 根目录。受信任的管理插件仍在主进程中执行。 workspace 附件副本可由用户写入，不是持久化原件。所需集成检查未完成时，不能接受发布。
